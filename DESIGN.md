# SE Tailoring interface

The application helps a project team describe its context, inspect provisional process recommendations, and record human tailoring decisions. It is a facilitated research instrument; software completeness does not establish project approval or method validity.

Home should make the next action clear while explaining the path from project context to a process plan. Keep the current dark surfaces, cyan interaction accent, existing type stack and semantic tailoring-level colors. Use readable working text, aligned quantities and quiet dividers. The project itself supplies the subject: context questions, process rigor, evidence and decisions.

On desktop, pair the introduction and start action with the three-step explanation. On phones, put the start action before that explanation, keep the three scope quantities together, and use a single column of compact reference links. Keep the research/privacy notice readable without dismissal. Saved work retains its prominent resume/report action and decision review; detailed framework information stays available through disclosure.

Preserve the 16-question, 22-process and three-level scope, uncertainty choices, recommendation explanations, approval qualifications, browser-local storage and private-backup boundary. Reference views support the assessment; they are not extra mandatory steps. A summary must not turn ordinal judgments into geometric or quantitative evidence.

Use the shared frontend design workflow for refinement. This surface benefits from hierarchy, spacing, typography and navigation improvements. Animated glyphs or a generated scene do not help the current assessment task. A static capture is unnecessary when the source is available; a before-and-after video is useful only for a requested presentation.

Assessment setup aligns with the working column; consequential boundary and purpose fields retain room for real text. Rating anchors use readable prose and retain native radio, preview, Unknown and inherited states. All section links remain available on phones, with back/next actions within reach while reviewing long criteria.

Results lead with completion counts, process recommendations and decision actions. The complete ordinal metric profile is available through disclosure, with its independent-row interpretation retained. Incomplete input produces an explicit preview message; a zero priority count does not imply a completed assessment. Preserve the current warning, floor and dependency explanations beside each recommendation.

Reports keep draft/pilot status, sharing implications and the process plan visible. Use sentence case for process names, clear distinctions between framework recommendations and local choices, and compact level totals. Detailed records remain available through disclosure and in complete exports; visual simplification cannot hide unresolved checks, decision drafts or external-approval limits.

Supporting views keep their task-specific structures: the library for independent assessments, the process list and detail for work aids, and the matrix/lifecycle/dependency references for traceability. Table row headings read as process names rather than repeated uppercase labels, while column headers retain their role. Keep decision actions aligned with the page heading instead of stretching buttons to match its height.
